# Lumina Screen Pipeline — Emergency Audit Report

**Status**: ✅ **PIPELINE OPERATIONAL**

## Problem Identified

The Lumina Screen resume screening pipeline **was not broken**—it had **missing Python dependencies**.

### Root Cause
```
RuntimeError: pdfplumber is not installed. Run: pip install pdfplumber
```

The pipeline's `pdf_parser.py` depends on `pdfplumber` (and other packages) to extract text from PDF resumes. Without these packages, the pipeline would fail immediately on the first resume file.

---

## Solution Applied

### 1. **Installed Missing Dependencies**
```bash
pip install -r lumina_screen/requirements.txt
```

Required packages:
- `pdfplumber>=0.7.0` — PDF text extraction
- `sentence-transformers>=2.2.0` — Resume embedding (384-dim vectors)
- `chromadb>=0.4.0` — Vector database for embeddings
- `numpy>=1.24.0` — Numerical operations
- `torch>=2.0.0` — PyTorch (required by sentence-transformers)

### 2. **Added Pipeline Initialization Script**
Created `lumina_screen/init_pipeline.py` to verify dependencies and configuration before running:

```bash

## How the Pipeline Works

### Flow Diagram
```
Resumes Folder (./resumes)
         ↓
   Watcher (300ms polling)
         ↓
   Dedup Check (processed.json)
         ↓
   PDF Parser (pdfplumber)
         ↓
   Embedding (all-MiniLM-L6-v2)
         ↓
   Matcher (cosine similarity)
         ↓
   [Score ≥ 0.40?]
      ↙        ↘
   YES         NO
    ↓           ↓
 Notify      Skip
    ↓
 page_hit.txt
```

**File**: `lumina_screen/config.json`

  "match_threshold": 0.40,
  "chroma_store_path": "./chroma_store",
  "jd_path": "./jd.txt",
  "page_hit_path": "./page_hit.txt"
}
```

## What Each Component Does

### `pdf_parser.py`
- Uses **pdfplumber** to extract text from PDF files
- Extracts name (heuristic from first 5 lines), email (regex), phone (regex)
- Returns: `{raw_text, name, email, phone}`

### `embedder.py`
- Uses **sentence-transformers** (all-MiniLM-L6-v2) to create 384-dim embeddings
- Chunks resume text (200 words, 50-word overlap)
- Stores embeddings in **ChromaDB** vector database
- Creates JD embedding on initialization
- Computes cosine similarity between resume and JD embeddings

### `watcher.py`
- Polls resume folder every 300ms (configurable)
- Detects new .pdf files by diffing directory state
- Works on Windows, Linux, macOS (no inotify required)

### `matcher.py`
- Compares resume similarity score against threshold
- Returns: `(score: float, shortlisted: bool)`

### `notifier.py`
- Sends OS desktop notifications (macOS: osascript, Linux: notify-send, Windows: PowerShell)
- Appends shortlisted resumes to `page_hit.txt`
- Thread-safe logging (prevents concurrent write corruption)

### `dedup.py`
- Tracks processed resumes in `processed.json` using SHA-256 hash of file contents
- Prevents re-processing of the same file across restarts

## Troubleshooting

### Q: Pipeline doesn't create page_hit.txt
**A**: Ensure:
1. Dependencies are installed: `pip install -r lumina_screen/requirements.txt`
2. JD file is not empty: `wc -c lumina_screen/jd.txt` (should be >0)
3. Resume threshold is reasonable: Check `config.json` `match_threshold` (0.40 default)

### Q: PDF extraction fails
**A**: Check if `pdfplumber` is installed:
```bash
python3 -c "import pdfplumber; print(pdfplumber.__version__)"
```

### Q: Embeddings are all zeros
**A**: Verify `jd.txt` is not empty and contains actual text:
```bash
cat lumina_screen/jd.txt
```

### Q: No resumes processed on startup
**A**: Check:
1. Resume folder path in `config.json`
2. PDF files are actually in the folder: `ls lumina_screen/resumes/*.pdf`
3. Check `processed.json` to see if files were already processed
